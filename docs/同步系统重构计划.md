# 同步系统重构计划

日期：2026-10-01。状态：相关模块已实现重构，并完成本轮回归与验证；结果见 [验证记录](同步系统重构验证.md)。

## 使用前提与产品规则

- 当前同步系统未投入使用；本次直接定义正式同步格式和本机工作记录，不提供当前实验实现的 vault、revision、scope、基线或恢复日志迁移。实施不删除用户已有本机或远端数据。
- 正式启用后的产品升级仍需要读取既有历史、迁移设置及恢复中断操作；“无需现有同步迁移”不代表未来升级可以丢弃数据。
- WebDAV 不要求提供 ETag、执行条件 PUT 或支持 LOCK。无 ETag 的服务端是正常支持路径。
- 同一用户不会让两个浏览器同时开启同步写入同一库。跨浏览器同时初始化、发布、升级和清理的竞争不属于本次实现与验收范围。
- 浏览器之间仍可能先后使用同步；停用期间的本机修改与另一端修改需要三方比较。单个浏览器内的多标签页、多个消息入口和后台任务仍需串行保护。
- 新旧设置的映射复用 shared/settings/migrate 和 migrateToCurrent.ts 的现有迁移链，不维护第二份字段对应关系。
- Schema 版本不变但增删设置项时，产品发布版本会变化。以实际运行扩展的版本作为快照来源版本，不读取可能滞后的 settings.pluginVersion 更新日志确认状态。
- 已确认正式发布版本严格递增，快照使用实际运行扩展版本；同一发布版本的同步结构必须一致，版本比较按数值分段而不是字符串排序。
- 旧客户端遇到更新的产品版本或不支持的设置版本/协议时暂停写入，升级后自动重新检查并恢复。
- 手动暂停、同步范围、是否允许后台同步均为本机偏好，不上传、不影响其他设备。
- 当前数据和本机工作记录清理未知、已废弃字段；历史保留原始内容和哈希，预览、恢复时再迁移和清理，继续现有历史保留策略。
- 无冲突变更自动合并；真实的用户数据分歧仍由用户选择本机、远端或保留两份，不按设备时间覆盖。
- 用户关闭同步时保留连接、凭据、本机数据和比较基线；断开连接与删除远端库是独立操作。

## 本次缩减的范围

取消当前实验同步格式到新格式的迁移、混合实验格式解码、旧格式日志转存、范围导入、协议在线切换、晚到旧客户端提交桥接、跨浏览器锁、ETag 能力门槛和双浏览器同时写入测试。

保留未来正式发布后的设置演进、版本阻塞恢复、历史按需转换、顺序使用多设备，以及单浏览器内部并发和故障恢复。不因排除跨浏览器同时写入而去掉本机 Web Lock、应用标记、操作身份和上传后校验。

## 自动演进与版本判断

| 元数据                | 含义                       | 处理                                                                             |
| --------------------- | -------------------------- | -------------------------------------------------------------------------------- |
| formatVersion         | 同步协议形状               | 本次直接定义首个正式格式，不为迁移实验版本而引入格式 2；未来不兼容协议变化再提升 |
| settingsSchemaVersion | 配置版本及字段含义变化     | 复用现有配置迁移链                                                               |
| pluginVersion         | 写出数据的实际运行扩展版本 | 同 Schema 下增删字段的版本判断，也用于保护整个新增类别                           |

不额外维护独立的 syncSchemaVersion，避免产品版本和同步版本重复登记。结构变化必须伴随发布版本变化，检查对此约束进行验证。产品版本是来源元数据，不应用到本机 settings.pluginVersion，也不更新用户的更新日志确认状态。

处理规则：

1. 原始输入先做传输大小、身份和哈希验证，版本元数据有严格校验。
2. 新产品版本、新配置版本或不支持的协议先返回可恢复阻塞；不先过滤掉它们的新字段再发布截断数据。
3. 配置版本较旧时，通过现有迁移函数转换；同配置版本的旧发布数据无需字段对应迁移。
4. 按当前设置结构投影：去掉已移除和未知成员，补齐新增字段的合法默认值，执行完整运行时校验。
5. 比较基线、本机和远端先统一为当前可比较结构，再做三方合并，避免版本/default 变化被当作用户编辑。
6. 原始输入与转换后的工作副本分开；原始哈希验证不受投影、补齐和顺序规范化影响。

字段改名、拆分、合并和类型转换不需要再定义一份同步映射：复用已经随配置版本提供的迁移函数，并确保全部同步入口都会调用它。

迁移函数目前接收完整设置，同步输入可能是过滤后的部分设置。实施时在现有迁移入口作必要适配或提取已有纯转换步骤，保证输入结构有效，保留字段存在性，不以类型强转伪装成完整旧配置。不能用当前版本默认值冒充旧版本完整数据。壁纸 IndexedDB 等副作用仍留在本机迁移层。

未知字段清理覆盖设置、数据类别、实体成员、基线、冲突与恢复记录及无引用资源索引。“不占空间”指不进入当前持久数据与新快照；读取、解析和原始哈希检查仍有有界临时内存。既有历史继续原样保留。

## 目标模块与实现约束

### 1. 设置处理：保留现有设置结构及迁移链

保留 CURRENT_CONFIG_SCHEMA、defaultSettings、normalizeCurrentSettings、settingsStorage 和已登记迁移；在此基础上增加简洁的投影和校验规则，收敛重复逻辑，不全面重写设置系统。

- 自动枚举当前结构，字段明确归类为同步或本机专用；结构变化不再需要多处同步白名单修改。
- 同步分类须明确，防止新增凭据、缓存和运行状态自动上传；类型、数组成员和枚举由必要的规则补充校验。
- 新增字段补齐默认值，删除字段从当前有效数据清理。
- 保留“未携带”“显式值”“实体删除”的区别；旧发布缺少新字段不能覆盖已有有效值。
- 同步和完整设置转换共享配置 10→11→12 的纯迁移注册，复用原迁移函数；WXT 存储迁移的注册及壁纸等本机副作用继续保留。
- 非法已知远端值拒绝应用，保留最后一次有效本机数据；可约束数值采用明确规则。

### 2. 快照处理：snapshotCodec.ts

负责版本判断、复用迁移、结构投影、校验及生成可比较工作快照。捕获、普通同步、历史、冲突、备份和恢复共用入口。

revision 和备份携带 formatVersion、settingsSchemaVersion 和来源 pluginVersion；本机范围不进入远端偏好语义。快照、commit 中的 scope 字段表示数据覆盖范围，由实际携带的类别生成，区分缺失类别与显式空集合；它不会合并到本机的同步开关。

既有本机 settings.pluginVersion 为更新日志确认状态，默认可为空，且可能等关闭更新日志才更新。快照来源版本从实际运行版本读取并写出。

### 3. 类别定义：domains.ts

静态集合收拢类别 ID、存储键、范围及覆盖信息，实体表统一删除记录处理。捕获、应用、可用性仍保留原有专用入口，避免为少量固定类别增加动态分发抽象；快捷链接、便签、搜索引擎和壁纸继续使用专用合并及事务。

移除类别后当前快照及本机工作数据清理；恢复旧历史时也按当前结构过滤。新类别由较新的来源发布版本保护，旧客户端不会写出丢弃类别的版本。

### 4. 本机状态与恢复：localState.ts + recovery.ts

分开连接身份与秘密、本机控制偏好、阻塞及错误、比较基线和执行进度。

- 用户暂停与故障阻塞分开；自动恢复不覆盖用户暂停。
- 全关闭是合法空范围，保留连接与数据。
- 类别停用期间保留该类别最后有效基线；发布其他类别时保留最新远端的停用类别，不以陈旧基线回滚远端。
- 重新开启后做三方比较；停用期间先后产生的真实分歧仍由用户选择。
- 升级或重启遇到未完成操作，先核实是否已发布/已应用；不清空日志后重复提交或重放旧值。
- 未提交的同步应用计划服从最新本机开关；范围改变时撤销旧计划并重新比较。手动导入使用独立来源标记和备份内容范围，不受云端范围限制。
- 应用日志替换与旧临时资源清理一起提交；恢复失败保留日志并允许打开本机界面。无应用日志时，启动不等待后台远端任务。
- 状态变更在同一浏览器串行，查询避免不必要的写入副作用。

| 状态               | 恢复行为                                                 |
| ------------------ | -------------------------------------------------------- |
| 用户暂停           | 用户开启后检查两端，后台不得擅自恢复                     |
| 未选择类别         | 保存空范围，选择类别后恢复                               |
| 版本过新           | 升级、启动或手动检查兼容性，支持后解除阻塞               |
| 凭据/授权失效      | 支持更新凭据或重新授权，无需断开清空基线                 |
| 加密未解锁         | 正确解锁后恢复，用户暂停仍有效                           |
| 空间不足           | 空间或资源处理后重试，保留本机未上传编辑                 |
| 数据超限           | 发布和落盘前拒绝，保留两端数据，缩减后重试               |
| 网络/限流/临时错误 | 有界持久退避重试，用户暂停时停止                         |
| 冲突               | 重新核实状态，仍有真实分歧则等待选择                     |
| 损坏               | 核实已确认修复，不自动跳过未解决的损坏版本               |
| 库丢失或身份变化   | 同一身份恢复后继续，不同身份需要明确接管，不自动覆盖重建 |

### 5. 执行与 WebDAV：沿用不可变 revision，收拢本机流程

- 不依赖 ETag、If-Match、If-None-Match 或 LOCK；不增加两浏览器分布式互斥。
- 每次操作有唯一 operationId/revisionId。先上传资源和独立 payload，上传后核对字节、大小与哈希，最后发布 commit。只有完整 commit 对应且验证通过的版本可应用。
- 在当前单写浏览器前提下，控制文件普通 PUT 后重新读取核验，初始化重复请求幂等；半成品不得被当作有效库。
- 无法确定服务端是否保存成功时，按操作身份查证后继续；重试不重写不同内容到同一个 revision。
- 数据检查、应用、维护和恢复命令共用本机队列；保留 Web Lock、草稿合并、应用前检查、一次普通数据提交与标记以及壁纸事务。
- 祖先不可追溯时利用已保存有效基线和删除信息；没有可信基线时给出明确恢复选择。
- 删除记录用于防止顺序使用的旧设备复活已删除实体；删除与修改仍有真实分歧时保留冲突。
- 网络重试进度持久化；如需后台定时重试，使用浏览器 alarms 并调整对应 Manifest，不做固定频率轮询。
- 同一浏览器的清理和发布串行；清理保留有效历史引用和暂存资源，不删除恢复所需文件。
- 远端缓存按不可变身份/哈希复用，设数量和字节上限，不保存完整未知数据。

## 实施顺序与验收

| 阶段              | 内容                                                 | 核心验收                                                     |
| ----------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| 0. 固定回归       | 保留已有有效回归，记录本轮缺陷                       | 缺陷在旧实现失败，已有通过行为仍可检查                       |
| 1. 设置处理       | 现有结构投影、完整校验、复用迁移                     | 同 Schema 增删字段、配置升级、嵌套/数组/非法值、未知字段清理 |
| 2. 快照处理       | 首个正式格式、来源 pluginVersion、类别与备份         | 新旧发布判断、哈希不变、转换幂等、默认值与缺失语义           |
| 3. 本机状态       | 本机范围、手动开关、恢复动作和工作记录               | 全关闭、重新开启、升级恢复、修复凭据/权限/空间               |
| 4. 执行与服务兼容 | 本机队列、无 ETag 提交、幂等、中断恢复、退避         | 无 ETag/忽略条件头的服务仍可用，响应丢失/重启不重复提交      |
| 5. 真实验收与 CI  | 单浏览器多页、两个客户端顺序使用、不同版本和故障注入 | 数据不丢、删除不复活、重复检查无多余版本、恢复无需重连       |

重点场景：

- 配置版本相同、来源产品版本不同：新增值保留，移除字段清理；旧端遇到新端数据暂停，升级后恢复。
- pluginVersion 来源不受更新日志未关闭、后台先启动或 settings.pluginVersion 为空影响。
- 版本比较覆盖 3.9.0 与 3.10.0、缺失/非法版本及升级后解除阻塞，不使用字符串字典序。
- 跨配置版本调用既有迁移，重命名/嵌套搬移/类型转换正确，不维护第二份映射。
- 用户暂停、空范围和版本阻塞共存时，恢复不越过用户控制。
- 两个客户端先后使用：停用期间各自编辑，重新启用正确合并，无需同时开启同步。
- 历史裁剪后未改的设备接受远端删除；恢复旧历史不会带回废弃字段。
- 当前/本机工作记录不保存未知字段；历史原始哈希不变，读取时完成迁移与过滤。
- 无 ETag、条件头被忽略；PUT 已保存但响应丢失、commit 未成功、资源部分上传及浏览器重启。
- 多标签页和重复消息触发下本机写入不丢；损坏、加密、壁纸临时资源和故障期间继续编辑。
- 便签投影和容量规则由本机保存、同步及备份共用；合并结果超限时不得先发布或部分应用。初次读取期间创建的草稿保留。
- 同步暂停、类别关闭时手动导入仍作用于本机；中断日志可恢复，替代日志不遗留临时壁纸。
- 远端目录删除、身份更换、凭据失效和权限收回分别进入正确状态。

真实扩展验证遵循 extension-browser-debugging Skill。纯回归接入 CI，运行 type-check、lint:check、对应构建和 diff 检查。构建成功不替代恢复及版本演进验收。
